1 Agent 基礎知識

Agent = LLM + 上下文 + 工具

這是實戰後濃縮的唯一公式。三個組件缺一不可，各自對應到不同層次的語言：

直覺實現學術 (RL)含義
🧠 大腦LLM策略 (Policy)決策核心 — 下一步做什麼
👁️ 眼睛上下文觀察空間 (Observation Space)能看到的所有資訊
🖐️ 手腳工具動作空間 (Action Space)能做的所有事情

ReAct 循環 — Agent 的心跳

所有 Agent 系統都在執行同一個基本循環：

💭 思考 (Think)

LLM 根據當前上下文決定下一步：是直接用自然語言回覆，還是需要調用工具？

🛠️ 行動 (Act)

若有工具調用需求，LLM 輸出結構化的 tool_call（工具名 + 參數）

👁️ 觀察 (Observe)

工具結果被加入上下文 → 循環回到思考

💡 關鍵洞察：2025 年後，先進模型（GPT-5、Claude 4、Kimi K2）已將工具調用能力「內化」為原生能力 — 模型自己決定何時調用、調哪個、傳什麼參數，無需人工編排。

Agent 的三種學習範式

範式方式類比人類
後訓練SFT / RL 改模型權重正式的學校教育
上下文學習提示詞、RAG、Skills翻閱參考書、用筆記本
外部化學習寫檔案、建立知識庫寫工作日記、沉澱 SOP

2 上下文工程

📌 核心命題：上下文品質決定 Agent 能力的真正上限。一個中等模型配上精心組織的上下文，往往勝過頂級模型在資訊匱乏下的盲目摸索。

API 的四種訊息角色

角色說明
system開發者寫的行為規則、身分定義、約束條件。最高優先級。
user終端使用者的輸入
assistant模型過去的回覆（含 tool_calls）
tool工具執行結果，透過 tool_call_id 關聯

Agent 的上下文構成（從最佔 token 到最核心）

  • 系統提示詞 — 角色定義、行為規則
  • 工具定義 — 工具名稱、描述、參數 schema
  • 對話歷史 — 使用者與 Agent 的互動軌跡
  • Agent 狀態 — 當前時間、工作目錄、已完成的步驟
  • 使用者記憶 — 從過去對話中提取的偏好與事實

KV Cache 友好的上下文設計

KV Cache 是大模型推理時復用歷史計算結果的機制。設計不良的上下文會破壞快取效率：

❌ 常見錯誤

工具定義無限膨脹、對話歷史無限制增長、每次請求重新載入相同靜態內容

✅ 最佳實踐

把高頻使用的內容放 context 開頭與結尾（注意力熱點）、按需動態載入 Skills、定期摘要壓縮歷史

3 使用者記憶與知識庫

從「無狀態對話」到「有記憶的夥伴」：

記憶的四層結構

🧠 Core Memory（本次對話）
↓ 定期寫入
📝 Working Memory（短期摘要）
↓ 跨會話讀取
📖 Long-term Memory（事實/偏好）
↓ 沉澱
🗂️ Knowledge Base（RAG + 結構化索引）
🔑 關鍵設計：OpenClaw 使用 MEMORY.md（Markdown 純文字）而非向量資料庫。好處是使用者可直接打開編輯、可 Git 版本控制、天然保留時間順序。

4 工具設計

五類工具總覽

工具類型調用方向作用對象範例
感知Agent 主動獲取資訊web_search, read_file, grep
執行Agent 主動改變世界shell_exec, write_file, edit_file

MCP 協議

Model Context Protocol — OpenAI 推出的開放標準，讓工具接入像安裝 Plugin 一樣簡單。任何支援 MCP 的 Agent 框架都能無縫使用同一套工具生態。目前已有數百個 MCP Server 覆蓋資料庫、瀏覽器、檔案系統等場景。

Coding Agent 的七個核心工具

1️⃣ Code Interpreter

隔離沙盒執行 Python

2️⃣ Bash Shell

終端命令執行

3️⃣ Read File

讀取檔案內容

4️⃣ Write File

建立或覆寫檔案

5️⃣ Edit File

局部修改

6️⃣ Glob (Search Files)

按模式搜檔名

7️⃣ Grep

搜檔案內容

這七個工具可覆蓋 95% 以上的開發任務

執行流範例：「分析上一季銷售資料並建立摘要報告」：

  1. 讀取 MEMORY.md → 發現使用者偏好 PDF 格式
  2. 透過搜尋取得 Google Sheets API 用法 → 寫 Python 腳本下載資料
  3. Pandas 聚合分析 → Matplotlib 畫圖 → 寫入 report.pdf
  4. 更新 MEMORY.md → 下次直接使用，不再詢問

6 評估 — 把表現變成可比較的信號

📊 第一原理：沒有評估，就沒有進步。評估讓你能分辨一次改動是真的變好了，還是只是運氣。

評估三要素

🌍 環境

工具調用 vs 人機互動 vs 仿真環境

📋 數據集

代表性測試案例、邊界情況、驗證集

📐 指標

成功率、完成時間、成本、LLM-as-a-Judge 評分

建立評估 → 發現瓶頸 → 定向改善 → 再次評估，形成完整的迭代閉環。

7 模型後訓練 — SFT 與 RL

🎯 核心論點：SFT 記憶，RL 泛化。資料與環境比演算法更重要。

三階段訓練全景

階段目標特性
預訓練世界知識 + 語言能力大量無監督數據
SFT 微調模仿特定行為模式精選標註數據；學會「照樣學樣」
RL 強化學習透過試錯自主提升獎勵信號驅動；學會「泛化策略」

SFT 擅長記憶大量事實與固定流程，RL 擅長發現新的策略與泛化到未見過的情況。後訓練是讓模型從「聰明」走向「專業」的關鍵。

8 自我進化 — 不改權重的成長

Agent 在不修改模型權重的前提下，透過兩個路徑持續變強：

📝 從經驗中學習

  • 策略摘要（提取成功模式）
  • 工作流錄製（重複任務固化）
  • 提示詞自動優化
  • Skills 知識外部化 → 沉澱為可重複使用的技能

🔧 發現與創造工具

  • MCP-Zero：Model 自主探索新 API
  • 開源工具整合
  • 用程式碼動態創造新工具
  • 從工具使用者 → 工具創造者

9 多模態與即時互動

Agent 從純文字世界走向物理世界：

領域核心挑戰代表技術
🗣️ 語音即時流式處理級聯 → 端到端全模態 → 全雙工
🖥️ Computer UseGUI 操作 (點擊/輸入/滾動)螢幕截圖 + 視覺理解
🤖 機器人VLA 模型控制Sim2Real 遷移

共同架構挑戰：即時性（低延遲感知與響應）vs 多模態（文字、語音、視覺、動作）的融合。
